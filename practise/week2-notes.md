**方案A-重建用户**（ai更为推荐）
  //创建用户，自动生成 /home/newuser
  sudo adduser newuser
  //加入sudo组
  sudo usermod -aG sudo newuser

  sudo cp -r /backup_code/opencv /home/newuser/

*2.虚拟机磁盘扩容*
经过一周的学习，  我发现上周配置虚拟机时只给20g是远远不够的，也可能是执行sudo apt update多了没清理导致缓存包积攒，反正系统提醒我磁盘空间不足，于是将磁盘扩容至64g。
**前置重要须知**
*- 分区操作存在风险，操作前必须备份Ubuntu内所有代码、配置文件（优先备份家目录项目文件夹）* **（快照！！！）**
*- 本次放弃外网无法访问的GParted Live官方镜像，使用国内教育网GXDE维护镜像，校园网/国内网络高速稳定*  （国外官方镜像下载真的特别慢，感觉几百MB要下6.7个小时；切换国内GXDE就非常快速了）
*- 全程禁止中途暂停、关闭、强制关机虚拟机，会导致分区损坏、系统崩溃*
一、前期准备：VMware硬件磁盘扩容（电脑端操作）
该步骤为提前操作，作用是给虚拟机分配额外磁盘空间，生成“未分配空间”，是系统扩容的前提
 1. 完全关闭Ubuntu虚拟机，打开【编辑虚拟机设置】
 2. 选中【硬盘(SATA)】，点击【扩展】选项
 3. 设置目标磁盘大小为 64G，等待硬件扩展完成
 4. 扩展后效果：虚拟机硬件上限变为64G，但Ubuntu系统仍只识别原20G，剩余44G为未分配空白空间，需分区合并

二、国内可用扩容镜像下载（替代海外镜像）
镜像优势：国内教育网镜像、无需科学网络、自带GParted分区工具、中文界面、适配所有VMware Ubuntu虚拟机
镜像地址：https://mirrors.cernet.edu.cn/GXDE/ISO/Maintenance-live/
下载选择：仅下载 amd64.iso 文件（64位虚拟机专用，排除arm64版本）

三、虚拟机挂载镜像并进入PE维护系统
3.1 挂载ISO镜像
1. 虚拟机关机状态下，打开【编辑虚拟机设置】→【CD/DVD(SATA)】
2. 选择【使用ISO映像文件】，选中下载好的GXDE维护镜像
3. 勾选启动时连接，点击确定保存配置
3.2 规避按键失败问题（百分百成功启动方式）
解决开机按ESC无反应、错过启动菜单的问题
1. VMware顶部菜单栏点击【虚拟机】→【电源】→【打开电源时进入固件】
2. 进入BIOS启动界面，将【CD-ROM Drive】调为第一启动项
3. 按F10保存并退出，虚拟机自动从镜像启动
3.3 进入桌面系统
1. 启动菜单直接选择默认【Live CD】（无需选择故障安全模式）
2. 语言选择【简体中文】，下一步进入桌面
3. 锁屏解锁密码：live（输入无显示，输完直接回车）

四、GParted分区无损扩容（核心步骤）
4.1 打开分区工具
1. 点击桌面左下角红色漩涡开始菜单，搜索并打开【GParted 分区编辑器】
2. 软件右上角磁盘选择 /dev/sda（虚拟机唯一硬盘）
4.2 正确扩容操作（关键避坑）
错误操作：拖动分区左侧滑块，会导致分区前移、扩容失败、系统引导异常
正确操作流程：
1. 右键分区列表中的 /dev/sda3（Ubuntu根分区，原19.5G）
2. 选择【更改大小/移动】
3. 固定分区左侧起点不动，仅拖动黄色分区条右侧滑块至最末端
4. 确认参数：之后的可用空间 = 0，所有未分配空间全部合并至sda3
5. 点击【调整大小/移动】确认配置
6. 点击软件顶部绿色对勾（应用全部操作），确认执行扩容
7. 等待进度条完整跑完，提示操作成功，点击关闭

五、恢复虚拟机正常启动配置（必做）
作用：关闭镜像优先启动，避免每次开机进入维护系统，恢复正常Ubuntu系统启动
1. 在GXDE系统内关机，回到VMware设置界面
2. 进入【CD/DVD(SATA)】设置
3. 取消勾选「启动时连接」（ISO文件可保留配置，无需删除）
4. 确认保存设置，恢复硬盘优先启动
六、扩容成功验证命令
正常开机进入Ubuntu系统，打开终端执行以下命令验证磁盘容量
**df -h**
成功标准：/ 挂载点（sda3）总容量显示 63.5G左右，即为扩容完成，磁盘空间不足问题彻底解决

七、本次扩容踩坑记录&避坑总结
海外GParted镜像无法访问、下载失败      境外镜像国内网络限制，教育网无法连通        替换为国内CERNET教育网GXDE维护镜像
  开机按ESC无法调出启动菜单               开机速度过快，错过按键时机             使用「打开电源时进入固件」固定启动项
 分区扩容后未分配空间跑到分区左侧            误拖动分区左侧起始滑块              撤销操作，仅拖动右侧滑块，保证前置空间为0
   扩容完成后反复进入PE系统               未取消CD/DVD启动时连接勾选                扩容后关闭镜像开机自启权限

八、扩容后环境修复（可选）
若扩容后出现软件环境异常、OpenCV无法使用，执行更新修复：
sudo apt update
sudo apt install python3-opencv

九、后续扩容通用模板（下次直接套用）
后续需再次扩容磁盘，仅需重复流程：VMware扩展硬件磁盘 → GXDE镜像启动 → GParted合并未分配空间 → 恢复启动项 → 命令验证
无需更换镜像、无需修改操作逻辑，全程通用。
